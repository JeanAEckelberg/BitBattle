
# Non Users
## Engine Developer
- As an Engine Developer I want to be able to make engine changes without worrying about application interop
- As an Engine Developer I want an easy way to spin up and test changes made to the engine
- As an Engine Developer, I want to be able to receive feedback, so that I can use it to guide further development
- As an Engine Developer I want to know the expected features of a standard competition
- As an Engine Developer I want to know what to work on and have what's assigned to me easily findable
- As an Engine Developer I want other's code changes to be well documented and tested before viewing it
# Users - Prior To competition
## Competition Developer
- As a Competition Developer I want to have unchanging and consistent APIs.
- As a Competition Developer I want well defined boundaries for engine and client behavior.
- As a Competition Developer, I want to be able to see metrics and logs to inform me of any potential issues, so that I can act on them before the competition starts.
- As a Competition Developer, I want to be able to develop the game logic in whatever language I am most familiar with.
- As a Competition Developer, I want to be able to create multiple types of games, such as games where players may be on a team together, or where players can only take certain actions on certain turns.
- As a Competition Developer, I want to be able to create different tournament methods, such as round-robin & elimination.
- As a Competition Developer, I want to keep my dependencies minimal, so that I can create the server quickly.
- As a Competition Developer, I don't want to have to worry about how the client and game engine connect so that I can focus on developing the game challenges.
## Competition DBA
- As a Competition DBA I want to be able commit data changes while the application is running.
- As a Competition DBA, I want to store the teams that are competing.
- As a Competition DBA, I want to store the games and points awarded to the teams.
- As a Competition DBA, I want to know which teams are competing in a game.
- As a competition DBA, I want to see the changes in the GameState during a game so that it can be visualized.
- As a competition DBA, I want to know what organization each team is from.
- As a competition DBA, I want to know the organizations competing in this competition.
- As a competition DBA, I want to know what category a team belongs to so I can award different prize categories
- As a Competition DBA, I want to be able to see the results of a specific tournament.
## Competition Artist
- As a Competition Artist I want to make an upload art without worrying about internal behavior of the engine
- As a Competition Artist I want the uploading and linking of assets to be my only interaction with the engine
## Competition Playtester
- As a Competition Playtester I want to have debugging tools in the visualizer
- As a Competition Playtester I want an easy way to replay or quickly iterate on existing competitions
# Users - During Competition
## Competitor
- As a competition competitor i want to write and test code for bots to compete in the competition.
- As a Competitor, I want to be able to submit a bot at anytime during the competition.
- As a Competitor, I want to be able to retrieve previous bots so that I can recover my code if I fail to maintain version control
- As a Competitor, I want to be able to select a previous submission as my active submission, so that I don't have to submit a bot that has the same functionality as an earlier one.
- As a Competitor, I want to be able to log output and see it when testing code, so that I can get information about potential crashes or unintended behaviour.
- As a Competitor, I want to know what the competition rules, tools, and actions easily available to me so that I can develop my bot against that information.
## Competition Supporter
- As a Competition Supporter, I want to be able to see if anyone is having issues without them reporting it so that I can respond to issues quicker.
- As a Competition Supporter, I want a quick and easy method to patch and redeploy different components without information loss.
## Spectator
- As a Spectator I want an easy way to view games I want to see.
- As a Spectator I want to be able to view previous games.
- As a Spectator I want a stream
## Competition DBA
- As a Competition DBA I want to make quick changes to data.
- As a Competition DBA, I want to be able to query data throughout the competition so I can report on information on the fly.
